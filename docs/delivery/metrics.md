# 产品与交付指标

## 指标原则

- 业务指标以 CloudBase `events`、`orders`、`try_on_tests`、`reports`、`provider_runs` 和 `share_entries` 为事实源。
- 每次迭代在 `BRIEF.md` 中选择少量主指标，记录发布前基线、目标、观察窗口和护栏指标。
- 当前没有生产只读查询证据，所有业务基线均为“待采集”，不得用测试数据代替。

## 核心漏斗

| 指标 | 口径 | 数据源 | 当前基线 | 建议观察窗口 |
|---|---|---|---|---|
| 自拍上传成功率 | `upload_selfie_success` / 上传尝试 | events | 待采集 | 7 天滚动 |
| 偏好提交率 | `preference_submit` / 自拍成功用户 | events | 待采集 | 7 天滚动 |
| 生成成功率 | `generation_success` /（成功 + 失败） | events / provider_runs | 待采集 | 日 + 7 天 |
| 预览到支付转化率 | 支付成功用户 / `preview_view` 用户 | events / orders | 待采集 | 7 天滚动 |
| 支付交付成功率 | 可查看已解锁报告的支付订单 / 支付成功订单 | orders / reports | 待采集 | 日 + 7 天 |
| 报告查看率 | `report_view` 用户 / 支付成功用户 | events / orders | 待采集 | 7 天滚动 |
| 分享访问率 | 有访问的分享条目 / 已创建分享条目 | share_entries | 待采集 | 7 天滚动 |

### 当前口径缺口

- `cloudfunctions/admin/overview.js` 的汇总 `visits` 当前等于时间范围内全部 events 数量，而趋势 `visits` 只计算 `page_view`，两者不可直接比较。
- 当前小程序业务代码中未发现 `page_view` 写入；建立访问漏斗前需要新增或确认外部来源。
- 事件记录同时使用 `type` 和 `eventName`，后台聚合虽兼容两者，但分析与导出应统一规范。

## 产品与质量护栏

| 指标 | 口径 | 当前基线 | 目标规则 |
|---|---|---|---|
| 退款请求率 | `refund_request` / 支付成功订单 | 待采集 | 迭代后不得显著恶化 |
| 生成 P95 时长 | `provider_runs.durationMs` 的 P95 | 待采集 | 按首轮基线设目标 |
| 生成重试率 | 有 retry 的生成任务 / 全部生成任务 | 待采集 | 按首轮基线设目标 |
| 全量测试文件通过率 | 退出码为 0 的测试文件 / 全部测试文件 | 16/34（47.1%） | 发布前 100%，或有逐项批准例外 |
| 后台生产构建 | `npm run build` | 通过 | 必须持续通过 |
| 严重缺陷数 | QA 标为发布阻塞的未关闭缺陷 | 待分类 | 发布前为 0 |

## 埋点与口径检查

现有核心事件包括上传、偏好、生成成功/失败、预览、换组、支付、报告查看、分享访问和退款请求。首次生产基线采集前需检查：事件命名是否在实现中一致、是否去重、用户/订单口径、时区、测试流量过滤以及缺失事件比例。
